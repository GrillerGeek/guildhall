# Planning artifact adapter spikes

Issue [64](https://github.com/GrillerGeek/guildhall/issues/64), October 18 2026.
Disposable prototypes outside the shipped plugin. No quest or production adapter
is implemented here.

## Result

OpenCode **1.19.3** and Pi **1.3.0** both support a browser review companion
connected to a specific persisted session. The same browser surface worked with
both: select a passage, attach it to a comment, send the feedback to the harness,
receive a response, save a proposal checkpoint, and reload the conversation.

The harnesses are real installed binaries. Model responses are generated by an
explicitly synthetic local OpenAI-compatible server. This verifies transport,
session recovery and bridge behavior; it does not establish reasoning quality,
paid-provider compatibility, or native hosted artifact support. No live model
calls, credentials, global installations, or personal configuration changes are
part of the probes. The initial Pi help invocation reported an unsuccessful
attempt to lock personal settings; subsequent probes used isolated directories.

## Reproduce

Requires Python 3.12+, the installed `opencode` or `pi` binary, and loopback socket
access. No dependency installation step is hidden in this prototype.

```bash
python3 spikes/planning-artifacts/probe.py opencode
python3 spikes/planning-artifacts/probe.py pi
```

Each run prints its temporary fixture path, host version, and JSON receipt.
The directory retains the isolated client files, synthetic session history,
proposal, review state, checkpoint and logs for inspection. Keep those generated
files outside the repository. The script uses temporary XDG and Pi directories,
does not forward API keys, and does not repurpose the user's HOME.

For manual browser review:

```bash
python3 spikes/planning-artifacts/probe.py opencode --serve
python3 spikes/planning-artifacts/probe.py pi --serve
```

Open the printed loopback URL, select text in the proposal, click **Attach
selected passage**, enter feedback, and click **Send to harness**. Save a
checkpoint, then reload. Stop the demo with Ctrl-C. These servers are temporary
local fixtures, not a multi-user service. `--fixture /absolute/disposable/path`
can resume a retained fixture for the same harness; do not point it at a real
project or use one fixture for both harnesses.

## Observed capabilities

| Capability | OpenCode | Pi | Owner |
| --- | --- | --- | --- |
| Send feedback and retrieve response | HTTP session API | JSONL RPC; wait for `agent_settled` | Harness |
| Reopen exact session and inspect history | Persisted session ID | Explicit session file and ID | Harness |
| Resume conversation after process restart | Passed | Passed | Harness plus adapter |
| Select text and attach a comment | Passed in Edge | Passed in Edge | Shared browser companion |
| Save and reload review conversation | Passed in Edge | Passed in Edge | Companion JSON state |
| Duplicate suppression and conflicting-ID refusal | Passed | Passed | Companion |
| Pending submission recovery without replay | Passed, seeded interruption state | Passed, seeded interruption state | Companion |
| Wrong session and stale checkpoint refusal | Passed | Passed | Companion |
| Unauthorized/cross-origin write refusal | Passed | Passed | Companion fixture token/origin checks |
| Direct concurrent editing of hosted document | Not implemented | Not implemented | Needs collaboration service |
| Shared interactive control state | Not exercised | Not exercised | Needs collaboration service |
| Remote collaborators and permissions | Not implemented | Not implemented | Needs collaboration service |
| Native hosted artifact link | Not established | Not established | Not supplied by this spike |
| Portable HTML export with offline review | Source retained; live controls need bridge | Same | Future export adapter |

The programmatic probes verify HTTP feedback/checkpoint operations, persisted
state, exact-session reconnect, another prompt after reconnect, duplicate and
session mismatch handling, and a stale checkpoint after editing the local
proposal. The pending-state case is deliberately seeded; it is not a process
kill at the send/ack boundary. Local edits are preserved by refusing a stale
checkpoint, not by performing an automatic three-way merge.

The separate browser exercise used selection and feedback controls, saved the
checkpoint, then reloaded and observed the saved passage, comment, response and
proposed disposition. These synthetic comments are probe data, not Jason's
decisions. Fixture checkpoints were inspected on disk. They demonstrate the
file-persistence path, not a committed implementation plan or IDD acceptance.

## Recommendation

Use one portable review document and feedback/checkpoint contract, with small
host adapters. OpenCode's server API and Pi's RPC are viable transport choices;
Pi does not require a bespoke terminal UI extension for this browser workflow.
An extension can later provide discovery and launch commands without owning the
document or changing its synchronization semantics.

Keep native Claude artifact and Codex/Space integrations as the richer hosted
paths. For OpenCode and Pi, distinguish two support levels explicitly:

1. A local companion for single-user chat, selection feedback and durable files.
2. A compatible hosted collaboration service for shared documents, concurrent
   edits, comments, permissions and remote access.

Do not grow these spikes into an additional hosting platform within issue 64.
Before production code, choose whether the first release supports the local
companion only or integrates an existing collaboration service. Do not assume
these harnesses inherit access to this session's ChatGPT Pages connector.

Production work still needs authenticated session binding, bounded input and
history handling, cancellation/timeouts, concurrency control, real ambiguity
recovery at the send/ack boundary, explicit acceptance actions, portable export,
and browser/accessibility validation. Preserve ordinary permission controls;
a browser feedback endpoint must not become an unrestricted shell or tool API.
