# Decision: explicit host evidence levels

The user approved the issue-resolution plan, including a separately qualified,
explicit configuration-evidence lane. Routing schema3 implements that proposal.
Execution-observed remains the setup default; configuration_verified must be
selected explicitly and changes the activation hash. Neither a helper report nor
this implementation approval activates routing in any project.

Version1/2 policies and hashes remain unchanged. No existing verified flag is
silently migrated. V3 qualification binds its objective and evidence requirement,
plus existing profile, host, report, revision and expiry checks. Concrete model
and effort observations stay separate. Missing nonnull requested effort prevents
strong qualification. Configuration-based qualification makes no served-model claim.

Native-Claude transcript and Codex app-server capture adapters only inspect
explicitly supplied task-owned records. The Codex desktop collaboration tool is
not presumed to expose app-server capture. If unsupported, preflight reports that
limitation instead of changing host/worker tool or relaxing the policy silently.

Local inspection on 2026-09-22 found Codex.app binary0.142.0-alpha.1 and running
ChatGPT.app Codex runtime0.154.0-alpha.6.2. Their schemas were generated without
model calls into temporary directories. The latter Thread schema labels model
and effort configuration; completions omit executed identity. The issue's
0.155 desktop environment was not reproduced. No personal logs were searched.

This is a capability and record-validation implementation, not a live adaptive
qualification. Independently reviewed records and quality measurements remain
required for each enabled host/profile/role/category.
